# 实现约束

本文件保存已确认的技术与实现决策。功能范围和验收标准以当前任务引用的需求资料为准。

## 固定选型

- TypeScript、Node.js；通信平台使用 Microsoft Teams SDK。
- Agent Runtime 使用 Pi SDK：`@earendil-works/pi-coding-agent`，通过 SDK 集成，不启动 Pi CLI 子进程处理请求。
- 日志集成采用 Kibana MCP；代码智能采用 `DeusData/codebase-memory-mcp`。
- 被分析的业务代码位于多个 GitLab 仓库；本项目使用 GitHub 管理。
- 部署采用 Docker，并保持 Kubernetes 兼容。

## 系统解耦

- Teams Bot 与 Agent Runtime 解耦，通信平台通过接口接入；MCP 连接管理与排障业务逻辑分离。
- 外部依赖均通过 Adapter 接口封装，提供真实与 Mock 实现。领域分层规则见 [领域设计约定](domain.md)。
- 第一版采用单 Agent 排障流程，不引入额外的 Agent Framework；不同用户的请求与会话支持并发。
- 排障流程由独立的 `bau-troubleshooting` Skill 定义。开发技能与生产运行时技能分别配置，生产仅加载审核过的排障技能。

## 第三方依赖验证

- 添加或升级依赖、修改 SDK 或 MCP 接入时，检查最新官方文档、实际安装版本的 API、许可证和生产使用风险；优先复用成熟项目，不重复实现现有 MCP 功能。
- 验证 Pi MCP Extension 加载方式、Codebase MCP 的真实工具契约、Teams 的身份认证与消息处理方式；示例须经实际版本验证后采用。
- 在当前任务的交付记录中列出依赖版本、验证方式与结果；尚未实测的兼容性结论标记为待验证。

## 生产安全实现

- 工具采用显式允许列表，未列出的工具默认拒绝。索引管理使用独立管理路径，不向普通用户或排障会话暴露。
- 每次调用前，由服务端基于可信身份、会话及资源范围执行授权检查；模型不能自行声明调用身份、角色或权限。
- 用户隔离覆盖会话、模型上下文、任务状态与缓存。向群组发送报告前校验对实际受众的可披露范围。
- 日志和工具结果中的敏感信息在发送给模型前脱敏；结合内容隔离、工具授权与输出校验防御 Prompt Injection，不能仅依靠 System Prompt。
- 工具审计记录调用人、会话、目标资源、授权结论、执行结果及证据版本；审计内容自身也要脱敏。

## 代码与证据版本

- 每个 GitLab 仓库仅分析已确认的 `main` 或 `master` 分支，支持多个仓库的同步、索引更新与版本校验。
- 诊断证据记录 Repository、Branch、Commit 和索引时间；过期或版本不明的证据须明确提示。

## 关键验证行为

核心行为可在没有生产凭据和网络依赖的 Mock 环境中验证。相关测试覆盖权限拒绝、模型调用前脱敏、用户与会话隔离、Prompt Injection、工具审计、代码与索引版本不匹配，以及外部依赖失败时的降级。
