# #16 — 同案补问与轮次生命周期

对应 [#16](https://github.com/GordonFP/bau-support-agent/issues/16) 与父规格 [#14](https://github.com/GordonFP/bau-support-agent/issues/14)。基于集成分支 `ad018b9`；验证日期：2026-10-20。

## 实现与验收

| 验收 | 实际可观察结果 |
| --- | --- |
| 客户编号定位 | 完整来源确认唯一申请时直接调查；多笔申请先补问提交时间，不选最新。补问保留问题 ID、所缺字段、最多 100 个脱敏候选及格式；partial／unknown／截断查询不作为唯一性证明。已验证选择第二个候选及其独立店铺集合。 |
| 可信回复 | `provideInformation` 校验案主、租户、固定会话、案件和当前问题，再检查当前授权。宿主按候选验证提交时间／选择；同一时间仍有多个候选时须明确候选。无效、无关、重复或模型生成内容不恢复调查。并发重复回复只建立一个新轮次。 |
| 等待与恢复 | 进入等待前使聚合旧轮失效、取消计时器及旧信号，并向捕获的旧轮发出 Agent abort；等待不启动新取证／模型。有效回复在同案递增 phaseId，重新获得 180 秒。原值选择映射仅在服务端内存保存，终态清理。 |
| 累计用量 | 同一预算 Port／案件预算引用贯穿轮次；调用 ID 含 phaseId，避免幂等结算覆盖旧费用。模型次数、已读日志记录数及查询覆盖累计；耗尽不能借补问恢复。未结旧模型的预留保留，迟到结果只以原调用结算／审计为 discarded，不进入新报告。 |
| 目标与重查 | 领域固定已选申请，报告核对目标与提交日期。入站、回复和私有候选在异步前取副本，外部修改不能改查目标。改变目标或终态后重查要求新案件，重新授权、取证并使用新代号及计数；旧案件账目仍保留。 |
| 计时与记录 | 注入单调时钟及期限调度器，验证 179 秒仍活动、180 秒停止，等待一小时不耗下一轮时间，旧轮计时器不能终止新轮。CaseView 保存接收／受理、各轮起止、人工等待／回复 UTC 记录；elapsedMs 从原受理点累计并包含等待，终态固定实际结束值。 |

测试复用 A（受理、补问、查询）、B（受控调用、Agent abort／close）、C（审计／预算）和 D（固定目的报告）公开边界。没有增加私有方法测试。按红灯→最小实现→绿灯逐项完成定位、恢复、计数、期限、目标、输入快照和审计拒绝切片；已实现保证再作边界回归。

领域的等待、轮次、目标与终态由同一 `TroubleshootingCase` 约束；应用管理时间、可信身份、预算 Port 和异步调用。每个调查闭包捕获自己的上下文、信号和输入；旧轮 catch／finally 不修改新轮视图或清理新轮映射。Agent abort／close 带可选 phaseId，以便适配器识别原轮；实际 SDK 仍须后续契约验证。
